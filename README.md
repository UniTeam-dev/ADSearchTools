# ADSearchTools

Нативное macOS-приложение для администрирования Active Directory: аналог «Active Directory Users and Computers» (ADUC) для Mac.

- **Навигация.** Дерево OU, как в ADUC (служебные контейнеры скрыты так же). Список объектов в виде строк с аватарами или таблицы с сортировкой. Панель деталей открывается справа.
- **Поиск** по всему домену через ANR (имя, логин, email), с фильтром «Все / Люди / Группы / Компьютеры».
- **Быстрые фильтры:** заблокированные, отключённые, пароль истекает в ближайшие 14 дней.
- **Пользователь:** профиль (редактирование по месту), учётная запись (статус, блокировка, последняя активность, срок пароля, «сменить при входе», «пароль не истекает», срок действия учётки), группы с основной группой, редактор атрибутов.
- **Операции:** сброс пароля с понятной ошибкой политики, разблокировка, включение и отключение, добавление и удаление из групп, перемещение между OU, удаление.
- **Создание** пользователя, группы, компьютера и OU.
- **Групповые действия** при множественном выборе.
- **Безопасность.** Подключение только по LDAPS (636). Пароль хранится в Связке ключей. Если сертификат DC не доверенный, приложение называет его CA и предлагает добавить его в доверенные.

Требования: macOS 13 Ventura или новее, Intel или Apple Silicon, доступ к контроллеру домена по порту 636.

## Установка (для коллег)

Откройте `ADSearchTools.dmg` и перетащите приложение в «Программы». Приложение подписано ad-hoc и не нотаризовано, поэтому при первом запуске:

- **macOS 15 и новее:** запустите приложение, закройте предупреждение, затем «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть».
- **macOS 13–14:** правой кнопкой по приложению → «Открыть» → «Открыть».

Подробности лежат в файле «Как установить.txt» внутри DMG.

## Сборка

Нужны только Command Line Tools (`xcode-select --install`), Xcode не требуется.

```sh
./scripts/build-dmg.sh          # → dist/ADSearchTools.app (universal) и dist/ADSearchTools.dmg
```

## Проверки

```sh
swift run ADKitChecks           # чистая логика: фильтры, DN, флаги, даты, SID/GUID
```

Тестовый контроллер домена (Samba AD, домен `CORP.LOCAL`, собственный CA `CORP-ROOT-CA`) поднимается так:

```sh
docker build -t adsearch-testdc TestDC
docker run -d --name adsearch-testdc --hostname dc01 --cap-add SYS_ADMIN -p 127.0.0.1:1636:636 adsearch-testdc
docker cp TestDC/seed.sh adsearch-testdc:/seed.sh && docker cp TestDC/photo.b64 adsearch-testdc:/photo.b64 && docker exec adsearch-testdc sh /seed.sh
```

Все операции записи на живом DC (создание, сброс пароля, блокировка и разблокировка, группы, перемещение, удаление):

```sh
AD_TEST_URL=127.0.0.1:1636 AD_TEST_USER=Administrator@corp.local AD_TEST_PASS='Passw0rd!Test' AD_INSECURE_TLS=1 swift run ADKitChecks
```

Сценарии интерфейса через модель приложения. Если задать `SELFTEST_SNAPSHOTS=<папка>`, самотест дополнительно сохранит PNG-снимки экранов:

```sh
AD_INSECURE_TLS=1 AD_TEST_PASS='Passw0rd!Test' swift run ADSearchTools --selftest
```

`AD_INSECURE_TLS=1` отключает проверку сертификата. Флаг нужен только для тестового DC, интерфейс его не включает.

## Устройство

| Часть | Что делает |
|---|---|
| `Sources/ADKit/LDAP.swift` | Синхронная обёртка над системным OpenLDAP (`import ldap`): bind, постраничный поиск, modify/add/delete/rename |
| `Sources/ADKit/AD.swift` | `ADDirectory` (actor): операции AD, переподключение после 15-минутного простоя; модель `ADObject` |
| `Sources/ADKit/ADTypes.swift` | Чистые функции: экранирование фильтров и DN, UAC, groupType, FILETIME, SID/GUID, тексты ошибок AD |
| `Sources/ADSearchTools/` | SwiftUI: окно подключения, главное окно, панель деталей, диалоги, Keychain, TLS-диагностика |

Решения, которые неочевидны из кода:

- **Сертификат CA.** Системный `libldap` проверяет TLS через Связку ключей и игнорирует путь к CA-файлу (`LDAPTLS_CACERT`). Поэтому сертификат CA импортируется в Связку как доверенный, а не указывается путём в настройках.
- **Диагностика TLS.** На недоверенный сертификат и на недоступный сервер `libldap` отвечает одной и той же ошибкой `-1`. Окно подключения само делает пробное TLS-рукопожатие и различает три случая: сервер недоступен, CA не доверенный (называет издателя), имя сервера не совпадает с сертификатом.
- **Третья колонка.** На macOS 13 `NavigationSplitView` не умеет скрывать третью колонку, поэтому список и детали лежат в `HSplitView`.
- **Последняя активность** берётся из `lastLogonTimestamp` и показывается приблизительно: атрибут реплицируется с задержкой до 14 дней.
- **Участники группы** загружаются запросом `(memberOf=<группа>)`, без постраничной выборки атрибута `member`, поэтому группы больше 1500 участников показываются полностью.

## Ограничения

- `LDAP.framework` помечен Apple как устаревший начиная с macOS 10.11, но есть и работает в macOS 27. Если Apple его удалит, слой `LDAP.swift` придётся заменить.
- Нет защиты OU от случайного удаления (это правка `nTSecurityDescriptor`), удаления поддерева, вкладок Exchange и RDP, делегирования прав. Удаление непустого OU AD отклоняет с понятной ошибкой.
- Фильтр «Пароль скоро истекает» ищет кандидатов по доменной политике `maxPwdAge`. Пользователи с более строгой гранулированной политикой паролей (PSO) могут в него не попасть.
- Смена области группы (глобальная, локальная, универсальная) недоступна: в AD её можно менять только цепочкой через универсальную.
